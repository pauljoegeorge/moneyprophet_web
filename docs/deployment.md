# Deploy Money Prophet to AWS

This is a generic deployment template. Replace `app.example.com`, `YOUR_FRONTEND_BUCKET`, `YOUR_ROUTE_FUNCTION`, and other placeholders privately. Do not commit real bucket names, AWS account IDs, distribution IDs, ARNs, API deployment origins, or credentials.

```text
Browser → Route 53 → CloudFront HTTPS → private S3 bucket
Browser → existing Rails API → Google OAuth
```

Use the existing `example.com` domain and hosted zone, with a separate bucket and CloudFront distribution for this app. The API stays on its existing host.

## 1. Certificate

In AWS Certificate Manager, select **US East (N. Virginia), `us-east-1`**. Reuse an issued certificate if its names include `*.example.com` or `app.example.com`. A certificate covering only the root domain does not cover this subdomain.

Otherwise request a certificate for `app.example.com`, select DNS validation, and create the validation records in Route 53. Wait for **Issued**. Keep the portfolio's existing certificate attached to its distribution.

## 2. S3 bucket

Create a bucket with your chosen private name (represented below as `YOUR_FRONTEND_BUCKET`), in your preferred region. Use ACLs disabled, Block all public access enabled, and default S3-managed encryption. Leave static website hosting disabled; CloudFront uses the regular S3 origin endpoint.

## 3. Production build and upload

Create `.env.production.local` in the repo:

```dotenv
VITE_API_ROOT=https://YOUR_PRODUCTION_API_DOMAIN
VITE_GOOGLE_MAPS_KEY=YOUR_BROWSER_MAPS_KEY
```

Use the actual HTTPS API origin without `/api/v1`. Omit the Maps key if not using maps. Configure an optional `VITE_GTM_CONTAINER_ID` if needed.

```bash
npm ci
npm run build
aws s3 sync build/ s3://YOUR_FRONTEND_BUCKET/ \
  --cache-control "public,max-age=0,must-revalidate"
```

Authenticate the AWS CLI using your normal account/profile; add `--profile YOUR_PROFILE` when needed. Substitute the actual bucket name if different. Do not add a public-read ACL.

Upload the contents of `build/`, not the source directory or a parent `build` folder. Expected objects include:

```text
index.html
app.html
sign_in/index.html
assets/
privacy.html
favicon.svg
apple-touch-icon.png
social-card.png
manifest.json
robots.txt
sitemap.xml
```

## 4. CloudFront distribution

Create a distribution with these settings:

| Setting               | Value                                                                |
| --------------------- | -------------------------------------------------------------------- |
| Origin                | Regular endpoint for the new S3 bucket, not an `s3-website` endpoint |
| Origin path           | Empty                                                                |
| Origin access         | Origin Access Control (OAC), sign requests                           |
| Viewer protocol       | Redirect HTTP to HTTPS                                               |
| Allowed methods       | GET, HEAD                                                            |
| Compression           | Enabled                                                              |
| Alternate domain name | `app.example.com`                                                    |
| Certificate           | Eligible certificate from step 1                                     |
| Default root object   | `index.html`                                                         |

Apply the bucket policy generated by CloudFront, either through its console workflow or **S3 → Permissions → Bucket policy**. It must permit this distribution to read the bucket. Keep public access blocked.

## 5. CloudFront route function

S3 does not automatically map `/sign_in` to `sign_in/index.html`. Create a CloudFront Function named `YOUR_ROUTE_FUNCTION`:

```js
function handler(event) {
  var request = event.request;
  var uri = request.uri;

  if (uri === "/" || uri === "/index.html") {
    request.uri = "/index.html";
  } else if (uri === "/sign_in" || uri === "/sign_in/") {
    request.uri = "/sign_in/index.html";
  } else if (uri.indexOf(".") === -1) {
    request.uri = "/app.html";
  }

  return request;
}
```

Save, then **Publish** the function so it has a **Live** version. Saving Development code alone is insufficient.

Open **Distribution → Behaviors → Default behavior → Edit → Function associations**. Select **CloudFront Functions**, **Viewer request**, and `YOUR_ROUTE_FUNCTION`. Save and wait for deployment. The function must belong to the same AWS account as the distribution.

The rewrite preserves the browser URL and query parameters, including the Google OAuth callback code. It serves pre-rendered public HTML at `/`, a noindex sign-in shell at `/sign_in`, and a noindex app shell for extensionless workspace routes. Static assets remain unchanged. Unknown extensionless routes also use the app shell; a true HTTP 404 policy would need additional edge/server routing.

Do not replace every S3 error with the landing page: that can hide missing assets and serve indexable landing HTML at private routes.

## 6. Route 53

In the existing `example.com` public hosted zone, create an **A alias** named `app` targeting the new CloudFront distribution. If CloudFront IPv6 is enabled, create an **AAAA alias** with the same target. Keep existing portfolio DNS records.

## 7. Google OAuth and API

In the Google Cloud project used by the API, open **Google Auth Platform → Clients → the Web application OAuth client**. Add this exact authorized redirect URI, without a trailing slash:

```text
https://app.example.com/sign_in
```

Retain `http://localhost:3001/sign_in` for development. This implementation uses server-side OAuth; authorized JavaScript origins are not required for that flow.

In **Branding**, use Money Prophet as the app name, `https://app.example.com/` as the homepage, and `https://app.example.com/privacy.html` as the privacy-policy URL. Add `example.com` as an authorized domain and configure support contact details. Add test users under **Audience** while testing; publish when ready and complete any verification Google requests.

In the Rails repo, ensure the production `GOOGLE_REDIRECT_URI` in `config/initializers/constants.rb` is exactly:

```ruby
GOOGLE_REDIRECT_URI = "https://app.example.com/sign_in"
```

Deploy/restart the API. Ensure API CORS permits `https://app.example.com` and retain any other required origins. OAuth credentials and client secrets stay on the server.

For maps, allow `https://app.example.com/*` in the browser Maps key's website restrictions and enable the APIs required by your map configuration.

## 8. Verify and switch links

Check the landing page, Google sign-in/callback, logout, expense creation, budgets, fixed bills, currency settings, and maps. Refresh `/dashboard` and `/expenses` directly. Check privacy, icons, and sitemap. View source at `/`: it should contain the landing text without JavaScript. The sign-in HTML and workspace shell should carry `noindex`.

Once the new app works, deploy the updated portfolio forwarding routes. They use `VITE_MONEY_PROPHET_URL`, defaulting to `https://app.example.com`.

Submit `https://app.example.com/sitemap.xml` in Google Search Console using an eligible verified property. Sessions from the old domain do not transfer.

## Subsequent releases

Use `sh deploy.sh` after filling in the ignored `.deploy.env` from `.deploy.env.example`. See the README for configuration. The script runs the build, upload, and invalidation, then waits for completion. The equivalent manual commands are below.

```bash
npm run build
aws s3 sync build/ s3://YOUR_FRONTEND_BUCKET/ \
  --cache-control "public,max-age=0,must-revalidate"
aws cloudfront create-invalidation \
  --distribution-id YOUR_MONEY_PROPHET_DISTRIBUTION_ID \
  --paths "/*"
```

Use the Money Prophet distribution ID, not the portfolio's. Upload before invalidating. The conservative cache headers favor freshness; an optimized deployment can cache hashed assets longer while retaining old assets for already-open clients. Keep a previous build artifact for rollback, then re-upload it and invalidate if needed.

## Troubleshooting

| Symptom                                                    | Check                                                                                                                                                                             |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Landing works but `/sign_in` returns `AccessDenied`        | Confirm `sign_in/index.html` is uploaded; publish and associate the viewer-request function. Try `/sign_in/index.html` directly to distinguish upload/access issues from routing. |
| `FunctionAssociationArn` invalid or function not published | Publish a Live version, use the function dropdown or its full ARN, and confirm the same AWS account.                                                                              |
| All pages return `AccessDenied`                            | Check the OAC, bucket policy, bucket name, and origin path.                                                                                                                       |
| Refreshing a workspace route fails                         | Confirm the viewer-request function rewrites it to `/app.html` and that object exists.                                                                                            |
| Google reports `redirect_uri_mismatch`                     | Match the GCP redirect URI and API production constant exactly; restart the API. Use `/sign_in`, not `/sign`.                                                                     |
| Sign-in button is disabled or shows retry                  | Inspect the `auth/google` API request, production API URL, CORS, and API availability.                                                                                            |
| Site still shows an older build                            | Confirm upload target, distribution ID, completed invalidation, and browser cache.                                                                                                |
| CloudFront certificate is unavailable                      | Check `us-east-1`, Issued status, and coverage for the subdomain.                                                                                                                 |
